# #95: Ground is a flyweight: tiles share their class's state until something writes to them

Hypothesis:
- Changes: Ground (CatchUp/Peek stop storing; new Ground.Write, the one tile write; per-tile state steps beside an unsaved class shadow and drops back when within tolerance), Trip/Travel (GroundRead.Estimate, GroundReadOf, the *Estimate reads go), World (unsaved shadow cache), tests that set up snow by mutating CatchUp's result.
- Affects: every ground read (travel minutes, hazard, contact wetting, search, burial, memory of ground); today an observed tile stores a private copy in World.Tiles (on main, after 30 populated days: 1 ground tile stored on seeds 17 and 23, since animals read the Estimate); what is read does not change because only weather writes ground today.
- Stays green: GroundTests (bar the store-on-read ones), TripTests, travel/NPC/herd tests, SaveFixtureTests after regeneration, determinism tests, ConservationGroundTests.
- First red: a new GroundTests test that reads a tile on a seeded world and finds no Ground in World.Tiles fails on the stored copy.
- Baseline (main, Release, 30 days Sim.Advance): seed 17 10.9 s, 4861 MB, save 835 KB, 1 ground tile; seed 23 7.3 s, 5358 MB, save 873 KB, 1 ground tile.

Revised (review): a layer-by-layer tolerance never drops a buried trench (packed snow under fresh stays far apart in compaction for weeks) → "within tolerance" compares what the ground reads as (snow depth, traversal factor, hazard, standing water, wetness, contact wetting), not its layers.
Revised (review): dropping at write time would swallow small writes, so repeated light trampling could never add up → Ground.Write always stores; the fallback is checked only as the tile's own state steps (and once before stepping, so a state loaded from an old save drops at its first read).
Revised (review): a shadow rebuilt for a tile lagging the class cache replays from the history start → the shadow is made at write time from the class at that minute (the cache is at or near now), and rebuilt only after a load or a sky change; Peek keeps the shadow it rebuilds (an unsaved cache).
Revised (review): CatchUp hands back the live own state but a throwaway class copy otherwise → reads only; Ground.Write is the one write, and the tests that set up snow by mutating CatchUp's result move to it.
Revised: seams for tests, decided unattended → Ground.CatchUp/Peek (reads store nothing, read the class), Ground.Write (own state steps, drops back, same minute however often looked at), Sim.Advance (30 populated days store no ground); travel and ground reads stay covered by the existing tests.
Revised: a drift's meltwater sits below the loam's retention and never drains, so reads-alike alone dropped a tile still 44% frozen that later thawed into different mud, while a held-water test never drops in dry weather → Close needs reads alike (snow and water depth 5 mm, mud 0.05, crust and ice, traversal, hazard and resting contact wetting 0.01) and water and ice held within 1 cm; the test drift (0.03 m water equivalent on a plain at 10 °C) drops between day 2 and 5.
Revised: GroundTests.BeforeTheFirstSubStep_NothingIsStored asserted a read stores the tile at the first sub-step; the spec ("Reading a tile never stores anything") inverts it → replaced by ReadingATile_StoresNothing_ItReadsItsClass.
Revised: GroundTests.SeededWorld_OpensOnAMonthOfGround asserted Same(ground, Tiles[camp].Ground) (stored on read) → that line removed; the month-of-ground checks stay.
Revised: GroundTests.GroundState_SurvivesSaveAndLoad stored ground by reading it → the tiles are given their own state by Ground.Write (a drift each), then saved, loaded and carried on as before.
Revised: GroundTests.TheActingAgentsTile_IsCaughtUpEveryMinute asserted the agent's tile is stored, caught up to the minute → renamed ..._IsReadEveryMinute_AndKeepsNoGround, asserting no ground is stored.
Revised: SurfaceViewTests, MemoryTests, VerbsTests, SubstrateTests, TripTests and Web GameHostTests set up snow or ice by mutating the state Ground.CatchUp returned (stored on read) → each writes it through Ground.Write; what they assert is unchanged.
Revised: KillChainTests.Ground_CarriedOnFromItsClass_IsTheLongWay compared the states CatchUp had stored → compares the states CatchUp returns in the warm and fresh worlds; same claim.
Revised: TracksTests.ATileWithNothingLeftOnIt_LeavesTheSave kept a tile by reading its ground → keeps it with a drift written by Ground.Write.
Revised: CarcassTests.Butcher_RunsItsTime asserted Tiles[camp].Carcasses is null, which relied on camp ground stored on read keeping the tile → reads Tiles.GetValueOrDefault(camp)?.Carcasses; the emptied tile now leaves the save, as its comment intends.
Revised: the save's shape is unchanged (TileState.Ground stays optional) and the fixture's three stored copies load as own states that drop at their first read → no format version bump and the fixture is kept as an old save that still loads byte for byte; regenerating it would only delete its Ground entries.
Revised: measured after (Release, 30 days Sim.Advance, the same probe): seed 17 9.2 s, 4850 MB (main 4861), save 835 KB (835), 0 ground tiles (1); seed 23 7.6 s, 5358 MB (5358), save 873 KB (873), 0 ground tiles (1). Animals now read the true ground at the Estimate's cost.
Revised (review): StepOwn checked Close before stepping, so every Write's own CatchUp threw away the last write if it was too small to read, and small writes never added up → Close is checked only after a sub-step; new test GroundTests.WritesTooSmallToRead_AddUp (ten 3 mm writes in one minute). A stored copy from an old save now drops at its first stepped sub-step instead of its first read.
Revised (review): CloseFactor also bounded HazardDelta and the wetting rate → renamed CloseReading; StepOwn's class column named classColumn; the bare 0 named currentWetnessPct; CatchUp's doc says a read can let a written tile go.
Follow-up: with no ground writer in play, Ground.Write, the shadows and the fallback are reached only by tests and old saves; the first writer (herds packing snow, #85 or later) should measure how many tiles keep their own state over 30 populated days, and whether each written tile's shadow replaying from the history start after a load stays cheap.
Follow-up: GroundRead now only says whether a written tile is stepped in place (Observe) or on a copy (Look); one read could serve both if previews may step written tiles in place.
